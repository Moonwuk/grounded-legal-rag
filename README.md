# grounded-legal-rag

Юридический RAG-ассистент для кейса ПСБ на Hack&Change 2026. Пользователь задаёт вопрос по базе документов, получает ответ с дословными основаниями и открывает соответствующий фрагмент в полном тексте. Если сведений недостаточно, ассистент запрашивает уточнение или объясняет пробел; техническая ошибка показывается отдельно.

Проект включает **веб-интерфейс для демонстрации** и **пакетное решение для конкурсной платформы**. Они используют одно ядро поиска и проверки ответов в `prototype/`. Интернет не используется как дополнительная юридическая база: источником служит переданный корпус.

**Демо:** <https://legal.77-221-140-87.sslip.io> — требуется выданный командой логин и пароль. Учётные данные и API-ключи в репозиторий не включаются. Адрес временный; воспроизводимый локальный запуск описан ниже.

## Быстрый старт: веб-чат

Нужны Git, Docker Engine или Docker Desktop с **Docker Compose v2**, свободный порт `8000` и доступ к интернету для первой сборки. Python и Node.js на хосте для Docker-запуска не нужны. Compose ограничивает контейнер 2 GiB памяти и двумя CPU; оставьте ресурсы также для Docker и системы.

Клонируйте репозиторий с доступом к нему и перейдите в каталог:

```bash
git clone https://github.com/Moonwuk/grounded-legal-rag.git
cd grounded-legal-rag
```

Для финальной сдачи используйте зафиксированный коммит. Запуск из корня проекта — одной командой:

```bash
docker compose up --build -d --wait
```

Откройте <http://127.0.0.1:8000>. Каталог и просмотр документов доступны сразу. В комплекте используется `organizer/knowledge-base.zip`: 21 документ, 1113 фрагментов в проверенной версии корпуса. Без API-ключа приложение сообщает, что модель не настроена; содержательных ответов в этом режиме нет.

Для подключения модели создайте локальный файл настроек, **если `.env` ещё не существует**:

```bash
cp .env.example .env
chmod 600 .env
```

Заполните в нём три переменные. Для текущего демо на публичном DeepSeek:

```dotenv
LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=<ваш API-ключ>
LLM_MODEL=deepseek-flash
```

Значение в угловых скобках замените реальным ключом. Для конкурсного запуска укажите **адрес, ключ и идентификатор модели, выданные организаторами**. Работа публичного DeepSeek не подтверждает совместимость с конкурсным прокси. Модель выбирается окружением, скрытой подмены провайдера нет.

Примените настройки:

```bash
docker compose up -d --wait
```

После изменения `.env` нужен `up`, чтобы Compose пересоздал контейнер с новым окружением; один `restart` настройки не перечитывает. Доступ к модели должен быть с сервера. Ключ остаётся на сервере и не передаётся в браузер.

| Режим | Что доступно |
|---|---|
| Без модели и без прокси | Интерфейс, каталог, поиск по названиям и просмотр документов |
| С моделью, без авторизующего прокси | Ответы и источники; диалог хранится только в памяти открытой вкладки браузера |
| С моделью, авторизующим прокси и серверной историей | Сохранённые диалоги, папки, корзина, свои подборки документов, остановка и очередь; доступ с разных устройств |

Корневой `compose.yaml` собирает **`web/Dockerfile`**. Корневой `Dockerfile` предназначен для отдельной пакетной задачи и не запускает сайт.

## Проверка основного сценария

1. Откройте сайт и раздел документов. На вкладке «Все» должен появиться каталог; найдите договор аренды с ООО «Северный Склад».
2. Задайте вопрос: **«Какова арендная плата по договору с ООО „Северный Склад“?»**
3. Проверьте смысл ответа по исходному договору: **450 000 рублей в месяц, включая НДС, пункт 3.1**. Формулировка модели может различаться; обязательны корректное основание и отсутствие выдуманных условий.
4. Нажмите карточку источника. Откроется документ с выделенным фрагментом. Сопоставьте цитату и ответ с полным текстом.
5. Продолжите диалог уточняющим вопросом. Для неоднозначного вопроса проверьте запрос уточнения; для отсутствующих в базе сведений — объяснение недостатка данных.
6. На телефоне проверьте ввод, открытие истории и документов из шапки и возврат к ответу.

При включённой серверной истории дополнительно:

- Создайте и переименуйте диалог, поместите его в папку. Откройте сайт на другом устройстве под тем же логином и обновите список.
- Во время ответа отправьте ещё два вопроса, поменяйте их порядок кнопками «Выше»/«Ниже», остановите ответ и продолжите очередь.
- Создайте свою вкладку документов через фильтры типа, редакции и названия. Убедитесь, что выбор сохранился после перезагрузки.
- Переместите тестовый диалог в корзину, восстановите его с источниками; затем проверьте окончательное удаление и отмену подтверждения на отдельном ненужном диалоге.

Состояние локального сервиса:

```bash
curl --fail http://127.0.0.1:8000/healthz
```

Ответ содержит `status`, число `documents` и `fragments`, состояние `dense` и сведения `skipped`. Это проверка загрузки приложения и корпуса, **не проверка доступности LLM**. В публичном демо служебный `/healthz` закрыт прокси и возвращает 404.

## Возможности интерфейса

### Диалоги

Панель «Ваши диалоги» содержит создание нового диалога, переименование, папки и корзину. Новый диалог создаётся в выбранной папке; удаление папки сохраняет её диалоги в разделе без папки. Название, заданное вручную, не заменяется после нового ответа.

История хранит вопросы, ответы, статусы и источники. Под одним логином она общая для всех устройств. Корзина позволяет восстановить диалог или окончательно удалить его после подтверждения. Автоматической очистки корзины нет. Формы и подтверждения реализованы окнами приложения.

### Остановка и очередь

Можно отправлять следующие вопросы, пока готовится ответ. В одном диалоге они выполняются последовательно с контекстом завершённых ответов. Очередь сохраняется на сервере; ожидающие вопросы можно удалить или переставить.

«Остановить» прерывает текущий обработчик и ставит очередь на паузу. «Продолжить очередь» запускает ожидающие вопросы. Если очередь пуста, «Повторить ответ» заново отправляет остановленный вопрос — это новая попытка, а не продолжение оборванного текста. Техническая ошибка также приостанавливает зависимые вопросы. Подробности — [очередь вопросов](docs/question_queue.md).

### Работа с ответами и поиск

Под ответом показаны точные выдержки: цитату можно развернуть или открыть в полном документе. Фрагменты одного документа объединены под одним заголовком, каждый сохраняет свой номер и переход. «Копировать с источниками» копирует полный ответ и все цитаты. «Печать / PDF» открывает системную печать всего текущего диалога; выберите «Сохранить как PDF». При запрете доступа к буферу текст открывается в собственном окне для ручного копирования.

Для ответа «Нужно уточнение» доступны поля недостающих сведений и кнопка «Продолжить». Названия полей берутся из словаря приложения; для старых ответов без этих данных показано общее поле уточнения. Черновик заменяется только после подтверждения.

В истории работает поиск по названиям, вопросам и ответам; выбранная папка дополнительно ограничивает список. В меню `⋯` находятся закрепление, переименование, перенос и удаление. Закрепления сохраняются на сервере. В открытом документе есть поиск с подсветкой, переходы ↑/↓ (также Enter / Shift+Enter) и «К цитате». На компьютере панель документов можно свернуть. Детали и воспроизводимые проверки — [удобство веб-интерфейса](docs/web_usability.md).

### Документы и подборки

Есть разделы «Все», «Законы», «Договоры», «Регламенты» и «Прочее», поиск по названию, просмотр полного текста и переход из ответа к цитате. Основные категории расположены сеткой без горизонтальной прокрутки; пользовательские подборки выбираются отдельным списком.

«Создать вкладку» собирает подборку **из существующей базы**. В форме доступны фильтры по названию, типу, редакции и переключатель «Только выбранные». Подборку можно переименовать и изменить; её удаление не удаляет документы. Подборки организуют просмотр, **но не ограничивают поиск ассистента**: ответ строится по всему корпусу. Загрузка новых файлов через интерфейс не предусмотрена. Подробности — [вкладки документов](docs/document_tabs.md).

### Мобильный экран

Диалог занимает экран, поле ввода находится снизу, история и документы открываются из шапки. Из источника можно вернуться к ответу. Enter отправляет вопрос, Shift+Enter добавляет строку. Анимация сопровождает состояния ассистента, включая необходимость уточнения; достоверность определяется проверками ответа и источниками. Подробнее — [мобильный интерфейс](docs/mobile_ui.md), [анимация](docs/web_animation.md).

## Конфигурация

Основной образец — [.env.example](.env.example); фактически передаваемые в контейнер значения перечислены в [compose.yaml](compose.yaml). Пустые необязательные настройки сохраняют значения ядра по умолчанию.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_BASE_URL` | пусто | URL OpenAI-совместимого API модели |
| `LLM_API_KEY` | пусто | Секрет доступа к API, только на сервере |
| `LLM_MODEL` | пусто | Идентификатор модели провайдера |
| `WEB_BIND`, `WEB_PORT` | `127.0.0.1`, `8000` | Адрес и порт приложения на хосте |
| `WEB_WORKERS` | `2` | Одновременные генерации на процесс веб-сервера, диапазон 1–8 |
| `WEB_REQUESTS_PER_MINUTE` | `30` | Общая минутная квота вопросов на логин при серверной истории |
| `WEB_REQUESTS_PER_DAY` | `300` | Общая суточная квота вопросов на логин при серверной истории |
| `WEB_MEMORY_LIMIT`, `WEB_CPUS` | `2g`, `2` | Ограничения памяти и CPU контейнера |
| `CHAT_PROXY_TOKEN` | пусто | Общий секрет приложения и авторизующего прокси; включает историю при доступном пути SQLite |
| `TOP_K` | `6` | Настройка числа кандидатов поиска |
| `MAX_TOKENS` | `8192` | Лимит токенов ответа модели; эффективный минимум 2048, при обрезке малый бюджет увеличивается до 4096 |
| `TEMPERATURE` | `0` | Температура генерации |
| `LLM_REASONING_EFFORT` | `low` | Уровень рассуждений; `default` не передаёт параметр провайдеру |
| `EMB_MODEL` | пусто | Модель эмбеддингов через тот же прокси; без неё работает BM25 |
| `PSB_DENSE_SECONDS` | значение ядра | Временной бюджет построения индекса эмбеддингов |
| `WEB_IMAGE` | `psb-web-web` | Имя веб-образа для Compose; при обычном старте собирается локально |

Compose задаёт `KB_PATH=/data/knowledge-base.zip` и `CHAT_HISTORY_PATH=/history/chats.sqlite3` внутри контейнера. При запуске вне Compose эти пути нужно задать самостоятельно, а каталог истории сделать доступным пользователю приложения.

Индекс эмбеддингов строится в фоне. До его готовности или при ошибке провайдера остаётся BM25; состояние отражается в `/healthz`. Дополнительные настройки ядра, ограничения повторов и поведение провайдеров — [гибридный поиск](docs/hybrid_retrieval.md) и [бюджет рассуждений](docs/reasoning_budget.md).

## Серверная история и внешний доступ

Для полноценного режима нужны HTTPS, аутентификация на обратном прокси и отдельный логин для каждого пользователя. Встроенной регистрации пользователей, восстановления паролей и MFA в приложении нет.

1. Сгенерируйте случайный секрет, например `openssl rand -hex 32`, и сохраните его как `CHAT_PROXY_TOKEN` в приватном `.env`. Тот же секрет передайте окружению прокси, не публикуя его в Git.
2. Настройте HTTPS и вход для **всего сайта**, включая API и статику. В текущем демо используется Caddy с Basic Auth.
3. После успешного входа прокси должен **перезаписывать** `X-Chat-User` проверенным логином и `X-Chat-Token` общим секретом. Значения, присланные браузером, доверенными не являются.
4. Сохраните исходный `Host`, удалите `Authorization` перед передачей в приложение и оставьте порт приложения на `127.0.0.1`. Закройте извне `/healthz`, `/docs`, `/redoc` и `/openapi.json`.
5. Выполните `docker compose up -d --wait` и проверьте вход, сохранение диалога и доступ с другого устройства. Без входа API не должен возвращать данные.

Фрагмент для Caddy **внутри `reverse_proxy` после настроенного `basic_auth`**:

```caddyfile
header_up X-Chat-User {http.auth.user.id}
header_up X-Chat-Token {env.CHAT_PROXY_TOKEN}
header_up -Authorization
```

Это часть конфигурации, а не готовый Caddyfile: домен, TLS, пользователи и закрытие служебных маршрутов настраиваются оператором. Переменная должна быть в окружении самого Caddy; `.env` приложения не передаётся ему автоматически. Если прокси находится в отдельном контейнере, его `127.0.0.1` не является адресом хоста — требуется соответствующая сетевая конфигурация.

После включения истории все `/api/*` требуют проверенную пару логин/секрет. Чужие диалоги, папки и подборки недоступны. Один общий логин означает общую историю: для изоляции нужны разные логины на прокси.

Прокси текущего демо настроен отдельно от репозитория. Сам `docker compose up` не создаёт публичный домен и не настраивает вход. Подробности хранения и API — [история диалогов](docs/chat_history.md).

## Архитектура и контроль достоверности

```text
Браузер → HTTPS / авторизующий прокси → FastAPI
                                         ├─ SQLite: диалоги, папки, подборки, очередь, квоты
                                         └─ ядро RAG
                                             ├─ корпус → фрагменты → поиск
                                             ├─ API модели → кандидат ответа
                                             └─ проверки → ответ, статус, источники
```

При старте сервер читает архив корпуса, извлекает документы и строит поисковый индекс. BM25 дополнен обработкой номеров положений, названий, связанных документов и редакций; эмбеддинги подключаются опционально. Тестовые вопросы и эталоны в рабочий индекс не входят.

Модель получает найденные положения и формирует кандидат ответа. Ядро проверяет существование источников, дословность цитат, числа, даты, расчёты, ссылки на положения и ограничения вывода. В веб-режиме предусмотрен отдельный проверяющий вызов модели; при непрошедшем контроле свободный текст не публикуется как подтверждённый вывод. В batch отдельный верификатор по умолчанию выключен ради бюджета — программные проверки остаются.

Браузер получает текст, статус и структурированные источники: документ, цитату и позиции символов в извлечённом тексте. По этим позициям открывается и подсвечивается основание. Возможны полный или частичный ответ, уточнение, недостаток сведений, выход за границы задачи, отказ и техническая ошибка. Проверка совпадения цитаты сама по себе не доказывает правильность юридического вывода.

Серверная история восстанавливается из SQLite по владельцу диалога. Очередь запускает генерацию в отдельном процессе, что позволяет остановить обработчик и соединение с провайдером. SQLite хранит завершённые ответы и ожидающие вопросы; история не зависит от открытой вкладки браузера.

Стек: Python, FastAPI/Uvicorn, SQLite, HTML/CSS/JavaScript без отдельной frontend-сборки. Ядро `prototype/` использует стандартную библиотеку Python. Зависимости веба закреплены в [web/requirements.txt](web/requirements.txt), базовый Docker-образ — по digest. Подробности — [архитектура RAG](docs/rag_architecture.md), [проверка текста](docs/prose_safety.md), [границы доказательств](docs/evidence_boundary_fix.md).

## Эксплуатация и диагностика

Команды выполняются из корня репозитория и относятся к проекту Compose `psb-web`:

```bash
# Состояние и последние сообщения сервиса
docker compose ps
docker compose logs --tail=100 web

# Пересобрать и применить выбранную версию исходников
docker compose up --build -d --wait

# Остановить, сохранив данные
docker compose stop

# Запустить остановленный сервис
docker compose start
```

Корпус подключён только для чтения. Его замена выполняется оператором: подготовить совместимый архив, заменить `organizer/knowledge-base.zip`, пересоздать контейнер и проверить загрузку и ответы. Исчезнувшие документы могут сделать старые источники недоступными; пользовательская подборка не является копией документа.

История находится в именованном томе `psb-web_chat-history`. Она переживает пересоздание контейнера и обычный `docker compose down`. **`docker compose down -v` удаляет том и историю** — для обычного обновления эта команда не нужна.

### Резервная копия истории

При включённой истории можно получить согласованный снимок работающей SQLite через backup API. Следующий пример рассчитан на стандартные пути Compose и создаёт новый файл в текущем каталоге:

```bash
umask 077
backup_file="chats-$(date -u +%Y%m%dT%H%M%SZ).sqlite3"
docker compose exec -T web python -c 'import sqlite3; src=sqlite3.connect("file:/history/chats.sqlite3?mode=ro", uri=True); dst=sqlite3.connect("/tmp/chats-backup.sqlite3"); src.backup(dst); dst.close(); src.close()'
docker compose cp web:/tmp/chats-backup.sqlite3 "$backup_file"
chmod 600 "$backup_file"
docker compose exec -T web python -c 'from pathlib import Path; Path("/tmp/chats-backup.sqlite3").unlink()'
```

Перенесите копию в закрытое хранилище вне репозитория. Она содержит пользовательские сообщения. Для восстановления сначала остановите приложение, сохраните текущий том и восстановите согласованную базу с правами пользователя контейнера `10001:10001`; не заменяйте SQLite работающего сервиса и не смешивайте её со старыми WAL-файлами. Проверяйте восстановление в отдельном окружении до замены рабочей базы.

### Типичные проблемы

| Симптом | Что проверить |
|---|---|
| Модель не настроена | Все три `LLM_*` в `.env`, затем `docker compose up -d --wait` |
| Техническая ошибка модели | URL, идентификатор модели, доступ и квоты провайдера, сетевую доступность с сервера; не публикуйте ключ или полное окружение |
| Нет истории, папок или очереди | `CHAT_PROXY_TOKEN`, доступность SQLite, аутентификацию и перезапись заголовков прокси |
| API возвращает 401 | Проверенный логин и совпадение секрета у прокси и приложения |
| Изменение возвращает 403 | Корректный внешний Host/Origin, обращение с того же сайта |
| Ответ 429 | Квоту вопросов на логин и `Retry-After`; удаление диалогов её не сбрасывает |
| Сервис занят | Число одновременных генераций и `WEB_WORKERS`; дождитесь завершения |
| Контейнер не стартует | `docker compose logs`, наличие файла корпуса, права тома, свободный порт и ресурсы Docker |
| На другом устройстве не видно изменений | Тот же логин; обновите список диалогов или подборок |
| Публичный `/healthz` возвращает 404 | Это ожидаемая защита демо; проверяйте healthcheck локально |

Для отдельного управляемого хостинга есть агенты Windows/Linux: [LOCAL_HOSTING](docs/LOCAL_HOSTING.md), [CI/CD](docs/CI_CD.md). Это другой вариант установки; инструкции и исторические сведения о его окружении не описывают автоматически текущее Caddy-демо.

## Безопасность и CI

Приложение и развёрнутое демо проверены в рамках [инженерного аудита от 15.11.2026](docs/web_security_audit_2026_11_15.md) с разбором OWASP. Это ограниченная проверка, а не сертификация или независимый пентест.

| Область | Реализованные меры |
|---|---|
| Доступ | HTTPS и вход на прокси; проверка секрета и владельца объектов на сервере; порт приложения только на localhost |
| Браузер | CSP, запрет framing, nosniff, ограничения Permissions-Policy; проверка Origin/Fetch Metadata для изменяющих API-запросов |
| Данные | Приватные ответы API без кеширования; тексты сообщений и ключи не пишутся в диагностические логи |
| Расход ресурсов | Конечные таймауты, ограничение параллелизма, размеры запросов и контекста; сохраняемые квоты вопросов при серверной истории |
| Контейнер | Non-root UID 10001, read-only root, `cap_drop: ALL`, `no-new-privileges`, tmpfs, отдельный том истории, read-only корпус |
| Ресурсы хоста | По умолчанию 2 GiB RAM, 2 CPU, 128 PID; ротация журналов 3 × 10 MiB |
| Сборка | Закреплённые зависимости и базовый образ; ограниченный контекст сборки через `web/Dockerfile.dockerignore`; ключи и история в образ не входят |

**Сканирование контейнера есть.** [Web CI](.github/workflows/web-ci.yml) на PR и push в `main` запускает регрессии, веб-тесты, проверки JavaScript, сборку/HTTP-проверку контейнера и поиск секретов. Подключённый [web-image workflow](.github/workflows/web-image.yml) проверяет Dockerfile, уязвимости ОС и библиотек образа, а также секреты внутри него. Порог уязвимостей образа — исправляемые HIGH/CRITICAL; ошибка сканера не считается успешным результатом.

[Полный Security scans](.github/workflows/security.yml) работает на `main` раз в два дня и по ручному запуску. В него входят Gitleaks, Bandit, CodeQL, pip-audit, проверки workflow и IaC, Hadolint, Trivy и проверки пакетного контейнера. После успешного общего gate формируется свежий `verified-submission`; это подтверждение перечисленных CI-проверок, а не официального Score. Публикация подписанного пакетного образа включается отдельно. Области анализа и пороги — [security_pipeline](docs/security_pipeline.md).

**Зафиксированный результат:** Web CI для `8ed1930` прошёл; в проверенном веб-образе на 15.11.2026 — 0 исправляемых HIGH/CRITICAL и 0 найденных секретов. Это не означает отсутствия всех уязвимостей. В исходном аудите полный Security gate оставался красным. Совместимость actionlint/zizmor затем исправлена закреплением reusable workflow полными SHA; анализ CodeQL и проверка SARIF обязательны, а публикация копии отчёта в не включённую по умолчанию панель GitHub Code Scanning запускается отдельно через `publish_code_scanning`. Статус готовности сверяйте с полным Security gate конкретного коммита; отчёт CodeQL доступен в artifact `security-codeql`. Подробные свидетельства и ограничения приведены в аудите.

Текущее демо обновляется вручную после проверок. Автоматическое продвижение именно того же проверенного и подписанного digest с обязательными gates и автоматическим откатом для него не настроено. Наличие CI также не доказывает включённую защиту ветки в настройках GitHub. Для конкурсного воспроизводимого запуска эти дополнительные механизмы не являются отдельным требованием кейса.

## Проверки для разработчика

Для ядра без реального API, из корня репозитория, Python 3.10+:

```bash
python3 -m unittest discover -s tests -v
python3 audit_retrieval.py
```

Для веба используйте отдельное окружение Python 3.13:

```bash
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r web/requirements.txt httpx==0.28.1
python -m pip check
python -m unittest discover -s web/tests -v
```

Frontend-проверки при установленном Node.js:

```bash
node --check web/static/app.js
node --check web/static/queue-ui.js
node --test web/tests/archive-scene.test.cjs
```

Браузерные сценарии находятся в `web/browser-tests/`: мобильная компоновка, история, папки, корзина, переименование, очередь, подборки, подтверждения и защита браузера. Настройка запуска и ограничения подмен описаны в [мобильном интерфейсе](docs/mobile_ui.md), [истории](docs/chat_history.md) и [очереди](docs/question_queue.md). Сценарии, создающие данные, запускайте на тестовом окружении: они не заменяют проверку реальной модели.

Независимые валидаторы:

```bash
python3 -m unittest discover -s evaluation/validator_tests -v
```

Проверки с заглушками не требуют платного API. Реальные прогоны описаны в [evaluation/README.md](evaluation/README.md); они требуют доступа к выбранному провайдеру и расходуют его лимиты. Некоторые команды обновляют `results/` или `dist/` — проверяйте diff перед коммитом.

## Пакетный сабмит платформы

Пакетный режим читает `questions.csv` и `knowledge-base.zip` из `DATA_DIR`, затем пишет `submission.csv` в рабочий каталог. Контракт — [технический регламент](organizer/technical_regulations_text.md). Платформа передаёт `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и `DATA_DIR`; ядро также поддерживает альтернативные имена `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `GEN_MODEL`.

Для локального прогона подготовьте каталог данных и передайте настройки модели **через окружение процесса**. Прямой запуск Python сам не загружает `.env` Compose:

```bash
DATA_DIR=/absolute/path/to/data python3 prototype/solution.py
```

Входной CSV содержит `id,question`, выходной — `id,answer`; ID сохраняются как строки. Для примера можно скопировать `organizer/demo_questions.csv` под именем `questions.csv`. `demo_output.csv` служит для сравнения человеком и не читается рабочим решением.

Основные настройки batch: `MAX_WORKERS=2` (максимум 8), `TOP_K=6`, `MAX_TOKENS=8192`, `TEMPERATURE=0`, `PSB_RUN_SECONDS=1100` (максимум 1150). `PSB_VERIFY=1` включает отдельный проверяющий вызов; по умолчанию применяется режим одного вызова с повторами при необходимости. Повторы ограничены числом попыток и общим временем; первая попытка каждого вопроса предшествует повторным попыткам остальных. Транспорт допускает до четырёх попыток на логический вызов; HTTP 429 вводит общую паузу для потоков одного процесса. Полностью технически неудавшийся вопрос может быть поставлен в конец batch-очереди ещё до двух раз в пределах общего дедлайна. Подробности — [смешанные ошибки прокси](docs/mixed_proxy_retries.md), [один вызов в batch](docs/one_call_answers.md), [бюджет и очередь](docs/batch_budget_and_reference_scope.md).

При отсутствии конфигурации создаётся CSV с техническими сообщениями, а процесс завершается с кодом 2. Такой файл не является успешным содержательным сабмитом.

Сборка и проверка архива перед отправкой:

```bash
python3 build_submission.py
python3 .github/scripts/check_submission.py
```

Результат — `dist/PSB_baseline_submission.zip`: `solution.py`, необходимые модули и `requirements.txt` в корне, без корпуса, вопросов, эталонов и ключей. Архив в ветке может отставать от исходников, поэтому перед отправкой его нужно пересобрать. Отдельный batch Docker/IaC описан в [deployment.md](docs/deployment.md) и [infra/ansible/README.md](infra/ansible/README.md).

## Ограничения

- Ответы ограничены предоставленным корпусом. Отсутствующий документ или редакцию нельзя заменить знаниями модели. Актуальность материалов вне корпуса не проверяется.
- Проверки источников и верификатор снижают риск ошибок, но не гарантируют юридическую точность, полноту или устойчивость к любым prompt injection. Нужны независимые смысловые проверки.
- На логин: до 100 активных диалогов, 100 в корзине, 30 папок и 30 подборок. На диалог: до 20 попыток вопроса с учётом резервов очереди; до пяти ожидающих вопросов и до 100 записей заданий за жизнь диалога. Контекст ограничен 30 000 символов, отдельный вопрос — 10 000.
- На ответ выделено до 150 секунд внутри политики; очередь ограничивает процесс вместе с запуском 180 секундами. Остановка закрывает соединение приложения, но не гарантирует прекращение обработки и начислений у провайдера.
- Квоты считают принятые вопросы, а не токены или деньги; работают при серверной истории и сохраняются после перезапуска. Один вопрос может потребовать нескольких вызовов API.
- SQLite не шифруется приложением. Постоянное удаление в интерфейсе не гарантирует физическое стирание из резервных копий и свободных страниц базы. Политику хранения, копирования и удаления задаёт оператор.
- Текущая конфигурация использует один процесс Uvicorn. Горизонтальное масштабирование и распределённая очередь не заявлены; несколько процессов меняют общий предел параллельных обращений к модели.
- Загрузка файлов пользователем, полноценное управление учётными записями, MFA и централизованные оповещения безопасности не реализованы.

Результаты внутренних прогонов, включая другие модели и аналог LLM-судьи, — [сводный отчёт](evaluation/reports/STABILITY_AND_FULL_HOLDOUT.md). Это не официальный Score. Проверки равнозначных формулировок и сохранения пояснений описаны в [claim_equivalence](docs/claim_equivalence.md) и [evidence_completeness](docs/evidence_completeness.md); сводка требований — [organizer_requirements](docs/organizer_requirements.md). Дополнительные границы — [архитектура RAG](docs/rag_architecture.md), история версий — [docs/history.md](docs/history.md).
