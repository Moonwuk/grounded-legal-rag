# grounded-legal-rag

Юридический RAG-ассистент для кейса ПСБ: поиск по документам, ответы с проверяемыми цитатами и контроль обоснованности выводов.

Состояние на 10 ноября 2026 года. Это исследовательский прототип для автоматической проверки, не финальная сдача проекта. Рабочий веб-интерфейс ещё не создан. Для существующей пакетной задачи добавлены Docker-образ, Compose и Ansible-развёртывание на подготовленный Linux-хост. Проверка через публичный DeepSeek API выполнена; это не запуск на прокси организаторов. Последний прогон структурной сборки — в [отчёте проверки](docs/structural_live_review.md); прежние попытки — в [отчёте границы выдачи](docs/evidence_boundary_fix.md).

## Проверка перед загрузкой

Исправлены воспроизводимые причины ошибок из аудита Ponytail: потеря точных номеров, неполные связанные изменения, недоступное цитирование коротких значений и неполезные отказы. Дополнительно устранён обход через подстроку: приложение публикует полный исходный блок по ID, сохраняя отрицания и условия внутри блока. После интеграции Docker/IaC проходят 166 штатных тестов и 5 отдельных тестов HTTPS fixture; поиск сохраняет 32/32 положительных сценария разработки. Это не доказательство юридической точности на скрытой выборке. Корпус с пустым файлом или неподдерживаемыми сносками DOCX отклоняется явно. Подробности — в [новом отчёте](docs/evidence_boundary_fix.md) и [исходном разборе](docs/root_cause_fixes.md). Предыдущий архитектурный аудит — [docs/pre_submission_audit.md](docs/pre_submission_audit.md).

Исторический прогон до исправления границы: 16 ответов без обнаруженных содержательных ошибок, одно замечание к полноте и один технический сбой. Прогон предыдущего ZIP 70ebed…: 17 PASS / 1 WARN, без технических и непроверенных ответов. Все промежуточные неудачи сохранены отдельно; рост официального Score не заявляется.

## Что внутри

- `PSB_next_step_report.md` — выводы из регламента и реального корпуса, изменения архитектуры, ограничения.
- `organizer/` — скачанные материалы; исходная база не изменялась. `technical_regulations_text.md` — текстовый экспорт регламента без встроенного изображения кнопки.
- `prototype/` — пять корневых Python-модулей и `requirements.txt`. Только стандартная библиотека Python, без скачивания моделей или пакетов во время запуска.
- `eval/cases.json` — 37 сценариев: 18 примеров организаторов и 19 добавленных проверок. Это набор разработки, не скрытые эталоны и не независимый тест.
- `tests/` — проверки загрузки, поиска, цитирования, политик, CSV и HTTP-контракта с имитацией модели; защита XML и тесты механизмов CI.
- `results/` — машинные результаты, инвентаризация корпуса с SHA-256, точные ограничения измерений.
- `dist/PSB_baseline_submission.zip` — отдельный архив в формате платформы. Содержит только необходимые корневые `.py` и `requirements.txt`, без вопросов, ответов и базы.
- `Dockerfile`, `containers/` — отдельный runtime-образ пакетной задачи, без корпуса и ключей.
- `deploy/`, `infra/ansible/` — Compose и IaC для подготовленного Linux-хоста: проверка происхождения образа, каталогов и прав, явный запуск batch-задачи. Порядок работы — [docs/deployment.md](docs/deployment.md).

## Проверить без API

Из каталога этого файла, Python 3.10+:

```bash
python3 -m unittest discover -s tests -v
python3 audit_retrieval.py
python3 build_submission.py
```

Результат проверки поиска не оценивает смысл ответов, устойчивость LLM или конкурсный Score. Сценарии созданы и использованы при разработке; нужен отдельный ещё не просмотренный набор.

## Запустить с прокси организаторов

Платформа сама задаёт `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и `DATA_DIR`. Поддерживаются альтернативы `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `GEN_MODEL`. Имя модели обязательно берётся из окружения, а не задаётся в коде.

Для локального прогона положите `questions.csv` и `knowledge-base.zip` в каталог данных, задайте доступ к разрешённому прокси через окружение, затем:

```bash
DATA_DIR=/absolute/path/to/data python3 prototype/solution.py
```

`submission.csv` создаётся в текущем рабочем каталоге. Для локальных примеров можно скопировать `organizer/demo_questions.csv` как `questions.csv`; файл `demo_output.csv` предназначен только для сравнения человеком и никогда не читается рабочим решением.

Настройки: `MAX_WORKERS` (по умолчанию 2, предел 8), `TOP_K` (6), `MAX_TOKENS` (8192), `TEMPERATURE` (0), `PSB_RUN_SECONDS` (1100, максимум 1150). На вопрос до четырёх логических вызовов генерации/проверки; для временных HTTP-ошибок до трёх сетевых попыток на вызов. `EMB_MODEL`, `RERANKER_MODEL`, `RERANKER_TOP_N`, `CHUNKER` в этой лексической базовой версии не используются.

При отсутствии конфигурации приложение создаёт CSV с сообщениями о технической проблеме и завершает работу с кодом 2. Это помогает проверить формат, но не даёт содержательных ответов.

## Что ещё проверить

1. Совместимость JSON-ответов и лимитов с реальным прокси и моделью платформы.
2. Качество ответов и отказов, ошибки смысловой проверки и устойчивость к неизвестным инъекциям.
3. Исторические и будущие редакции, многодокументные запросы, скорость полного набора.
4. Пользу эмбеддингов и реранкера относительно этого воспроизводимого базового варианта.
5. Отдельный финальный интерфейс, демонстрацию и проверку развёртывания на выбранном целевом хосте.

Исходный код базового решения создан для этой задачи. Материалы организаторов сохранены отдельно; здесь не заявляется право публиковать их под лицензией нашего кода.

## Исправления после реального API-прогона

Свободный текст `missing` и `clarification` больше не выводится пользователю. Приложение формирует сообщения о пробелах и уточнения из фиксированных шаблонов; модель может выбрать только допустимые коды `requested_facts`. Юридические выводы проходят через `claims` с существующими цитатами и смысловой проверкой. Это закрывает обнаруженный обход через пояснение отказа, но не гарантирует безошибочность модели или защиту от всех инъекций.

Загрузчик принимает TXT, MD и DOCX (основной текст и таблицы word/document.xml; не OCR и не сложные поля/колонтитулы). Для DOCX позиции относятся к извлечённому тексту. Внешние ссылки и макросы не исполняются. При неизвестном формате или неисправном файле загрузка завершается ошибкой, а не молча теряет документы.

Измерения поиска: `python3 audit_retrieval.py`. Сокращение контекста проверено на наборе разработки и нуждается в независимой оценке. Выбор TOP_K=6 не означает ограничения шести документов: связанные документы и соседние фрагменты добавляются отдельно.

Исследование навигации и путь масштабирования: [docs/retrieval_scaling.md](docs/retrieval_scaling.md). Разбор предложений по безопасности: [docs/security_review.md](docs/security_review.md).

Текущий поиск остаётся локальным BM25 в памяти и не является готовой распределённой поисковой системой. Векторная БД, гибридный поиск, структурированные правила применимости редакций и ACL пока не реализованы. Реальные юридические ответы используют только предоставленный корпус. Интернет использовался при разработке для изучения технологий, а не как источник ответов ассистента.

## Автоматические проверки безопасности

[Security scans](.github/workflows/security.yml) запускается для PR, изменений `main`, вручную и еженедельно. Включены Gitleaks, Bandit, CodeQL `security-extended`, pip-audit, actionlint, zizmor, проверки IaC, Hadolint, Trivy для Dockerfile/образа и регрессионные тесты на Python 3.11–3.13 и 3.15. Контейнер проходит запуск с локальной HTTPS-заглушкой модели; настоящие ключи LLM не требуются.

Общий статус `Security gate` требует успеха всех обязательных проверок, включая ошибки самих сканеров. Только после него создаётся artifact `verified-submission` со свежим ZIP. Его название означает прохождение перечисленных CI-проверок; совместимость с API организаторов и юридическая точность требуют отдельной оценки.

Области анализа, пороги, отчёты, ограничения и настройка обязательной проверки перед слиянием: [docs/security_pipeline.md](docs/security_pipeline.md).


## Граница выдачи полных исходных положений

Исправления отрицаний, обрезанных условий, отсылочных оснований и ограниченного восстановления после обрезки генерации описаны в [docs/evidence_boundary_fix.md](docs/evidence_boundary_fix.md). Модель выбирает ID; приложение восстанавливает исходный текст и формирует сообщения о распознанных отсутствующих статьях. Полнота и применимость всё ещё требуют смысловой проверки.

Последний реальный прогон предыдущего ZIP (70ebed…): 18 demo за 340,305 с, 0 технических и 0 непроверенных ответов; ручная оценка 17 PASS / 1 WARN. Предыдущая неудачная попытка и отдельные 8 новых синтетических сценариев сохранены отдельно. Эти результаты не являются официальным Score и не подтверждают API организаторов. Версии архивов, проверки и ограничения — в профильном отчёте.

## Структурные зависимости выбранных источников

Вводная норма распознанного плоского перечня теперь сохраняется вместе с выбранным элементом до проверки и публикации. Причина, регрессии и границы — [docs/structural_dependencies.md](docs/structural_dependencies.md). Новая сборка проверена 164 штатными тестами и 5 HTTPS-тестами; реальный прогон DeepSeek Flash завершён: 18 строк за 316,036 с, без технических и непроверенных ответов, 30/30 точных цитат. Ручная проверка полезности: 14 PASS / 4 WARN; внешний оценщик V4 Pro не завершил подготовку. Подробности и ограничения — в [отчёте](docs/structural_live_review.md).
