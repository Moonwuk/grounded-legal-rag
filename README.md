# grounded-legal-rag

Юридический RAG-ассистент для кейса ПСБ (Hack&Change 2026). Отвечает на вопросы
только по предоставленной базе документов, к каждому выводу приводит дословные
положения с адресом в документе, проверяет ответ программно и вторым вызовом
модели, а при нехватке сведений называет конкретный пробел. Одно ядро работает в
пакетном сабмите платформы (`submission.csv`) и в веб-чате с просмотром источников.

## Быстрый старт: веб-чат

```sh
docker compose up --build
```

Откройте <http://127.0.0.1:8000>. Каталог документов и просмотр источников
работают сразу; для ответов задайте доступ к модели в `.env` (образец —
[.env.example](.env.example), ключей в нём нет) и перезапустите
`docker compose up -d`:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | OpenAI-совместимый прокси и модель | пусто — чат отвечает «Модель не настроена» |
| `WEB_PORT`, `WEB_BIND` | порт и адрес на хосте | `8000`, `127.0.0.1` |
| `WEB_WORKERS` | одновременных запросов к модели | `2` |
| `EMB_MODEL`, `PSB_DENSE_SECONDS` | эмбеддинги того же прокси для гибридного поиска и бюджет индексации | пусто — только BM25 |
| `LLM_REASONING_EFFORT`, `MAX_TOKENS`, `TEMPERATURE`, `TOP_K` | настройки генерации и поиска; пусто — значение решения | `low`, `8192`, `0`, `6` |

**Проверка сценария:** спросите «Какова арендная плата по договору с ООО
„Северный Склад“?» — ответ «450 000 рублей в месяц, включая НДС (п. 3.1)» с
источником; нажмите карточку источника — справа откроется договор с выделенным
пунктом 3.1. Состояние сервиса — <http://127.0.0.1:8000/healthz>.

- Индекс эмбеддингов (`EMB_MODEL`) строится в фоне после старта; пока он строится или при ошибке провайдера чат работает на BM25. Состояние — поле `dense` в `/healthz`.
- Сборка веб-образа использует `web/Dockerfile.dockerignore`: Docker Compose v2 (BuildKit) применяет его вместо корневого `.dockerignore`, который относится к пакетному образу. В контекст попадают только `prototype/*.py` и файлы `web/`.
- Вопрос отправляется клавишей Enter; Shift+Enter переносит строку.
- Зависимости веб-сервиса зафиксированы в [web/requirements.txt](web/requirements.txt). Для тестов установите также `httpx==0.28.1` и запустите `python -m unittest discover -s web/tests -v`.
- История хранится в памяти вкладки. Сервер ограничивает время обработки запроса 150 секундами, браузер ждёт до 180 секунд. Для внешнего демо нужен доступ к модели и отдельная защита на обратном прокси.

[Руководство](docs/web_guide.md) · [Роадмап](docs/web_roadmap.md) · [Хостинг: Windows и Linux](docs/LOCAL_HOSTING.md) · [CI/CD](docs/CI_CD.md)

## Как устроено

Поиск (BM25 с номерами пунктов, связанными документами и датами редакций;
эмбеддинги при `EMB_MODEL`) → модель выбирает положения и пишет ответ →
программные проверки (числа, даты, расчёты, редакция на дату события, запреты,
выдуманные разделы и отсутствующие документы, инъекции) → проверяющий вызов →
приложение собирает ответ из дословных положений. Подробно —
[памятка архитектуры RAG](docs/rag_architecture.md).

## Что внутри

Коротко об устройстве поиска, ответа и контроля достоверности — [памятка архитектуры RAG](docs/rag_architecture.md).

- `PSB_next_step_report.md` — выводы из регламента и реального корпуса, изменения архитектуры, ограничения.
- `organizer/` — скачанные материалы; исходная база не изменялась. `technical_regulations_text.md` — текстовый экспорт регламента без встроенного изображения кнопки.
- `prototype/` — ядро: корпус, поиск, модель, политика ответа и `solution.py`; только стандартная библиотека Python, без скачивания моделей или пакетов во время запуска.
- `web/` — веб-чат (FastAPI) и интерфейс просмотра источников.
- `evaluation/` — независимые корпуса, эталоны, оценщики и аналог судьи регламента: [команды стенда](evaluation/README.md), [сводный отчёт прогонов](evaluation/reports/STABILITY_AND_FULL_HOLDOUT.md).
- `eval/cases.json` — 37 сценариев разработки (18 примеров организаторов и 19 добавленных); не скрытые эталоны и не независимый тест.
- `tests/` — проверки загрузки, поиска, цитирования, политик, CSV и HTTP-контракта с имитацией модели; защита XML и тесты механизмов CI.
- `results/` — машинные результаты, инвентаризация корпуса с SHA-256, точные ограничения измерений.
- `dist/PSB_baseline_submission.zip` — архив в формате платформы (корневые `.py` и `requirements.txt`, без вопросов, ответов и базы). Пересобирается командой `python3 build_submission.py` перед отправкой; в ветке может отставать от кода.
- `Dockerfile`, `containers/` — отдельный runtime-образ пакетной задачи, без корпуса и ключей.
- `deploy/`, `infra/ansible/` — Compose и IaC для подготовленного Linux-хоста: проверка происхождения образа, каталогов и прав, явный запуск batch-задачи. Порядок работы — [docs/deployment.md](docs/deployment.md).

## Пакетный сабмит платформы

Платформа сама задаёт `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и `DATA_DIR`. Поддерживаются альтернативы `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `GEN_MODEL`. Имя модели обязательно берётся из окружения, а не задаётся в коде.

Для локального прогона положите `questions.csv` и `knowledge-base.zip` в каталог данных, задайте доступ к разрешённому прокси через окружение, затем:

```bash
DATA_DIR=/absolute/path/to/data python3 prototype/solution.py
```

`submission.csv` создаётся в текущем рабочем каталоге. Для локальных примеров можно скопировать `organizer/demo_questions.csv` как `questions.csv`; файл `demo_output.csv` предназначен только для сравнения человеком и никогда не читается рабочим решением.

Настройки: `MAX_WORKERS` (по умолчанию 2, предел 8), `TOP_K` (6), `MAX_TOKENS` (8192), `TEMPERATURE` (0), `PSB_RUN_SECONDS` (1100, максимум 1150). `LLM_REASONING_EFFORT` — уровень рассуждений модели (`none`/`low`/`high`/`max`; по умолчанию `low`, `default` не передаёт параметр). Если ответ обрезан, а рассуждения заняли почти весь `MAX_TOKENS`, повтор с более высокого уровня идёт на `low` (ниже `low` уровень автоматически не опускается); если провайдер отвергает параметр (HTTP 400/422), запрос повторяется без него, и, если повтор без него успешен, до конца запуска параметр не передаётся ([основание](docs/reasoning_budget.md)). Форма ответа и названия источников — [docs/answer_form.md](docs/answer_form.md). В batch по умолчанию один вызов модели на ответ и повтор только при провале программной проверки; `PSB_VERIFY=1` включает отдельный проверяющий вызов ([почему](docs/one_call_answers.md)). На вопрос до пяти логических вызовов генерации/проверки ([основание](docs/contrast_and_restricted_answers.md#3-повтор-после-неудачного-сокращения-и-без-непрошенных-положений)); для временных HTTP-ошибок до трёх сетевых попыток на вызов; ответ модели вне JSON повторяется один раз с напоминанием о формате, повторная ошибка формата — технический статус. Если задан `EMB_MODEL`, к лексическому поиску добавляются кандидаты по эмбеддингам через тот же прокси (`PSB_DENSE_SECONDS` — бюджет индексации; при ошибке остаётся BM25, [подробнее](docs/hybrid_retrieval.md)). Реранкер `RERANKER_MODEL` подключается только при `PSB_RERANK=1` ([почему](docs/hybrid_retrieval.md#реранкер-только-по-флагу-psb_rerank1)); `RERANKER_TOP_N` и `CHUNKER` не используются.

При отсутствии конфигурации приложение создаёт CSV с сообщениями о технической проблеме и завершает работу с кодом 2. Это помогает проверить формат, но не даёт содержательных ответов.

В batch первая попытка каждого вопроса предшествует повторным попыткам других.
Проверенный полный ответ сохраняется без повтора ради формулировки; незавершённые
и частичные ответы получают оставшееся время. Отсутствие статьи по ссылке
не блокирует прямой ответ, если отдельная проверка подтверждает его независимость
от этой статьи; предупреждение о пробеле сохраняется.
[Бюджет, границы проверки и регрессии](docs/batch_budget_and_reference_scope.md).

## Проверить без API

Из каталога этого файла, Python 3.10+:

```bash
python3 -m unittest discover -s tests -v
python3 audit_retrieval.py
```

Архив для отправки на платформу собирается и проверяется отдельно, перед отправкой
(перезаписывает `dist/`):

```bash
python3 build_submission.py && python3 .github/scripts/check_submission.py
```

Результат проверки поиска не оценивает смысл ответов, устойчивость LLM или конкурсный Score. Сценарии созданы и использованы при разработке; нужен отдельный ещё не просмотренный набор.

Полный набор локальных проверок и прогоны с моделью — [памятка архитектуры, раздел 6](docs/rag_architecture.md#6-как-проверяется).

## Автоматические проверки безопасности

[Security scans](.github/workflows/security.yml) автоматически запускает сканеры только на `main` раз в два дня. На каждом PR и push в `main` работают веб-проверки, регрессионные тесты и быстрый поиск секретов Gitleaks. Полный скан можно запустить вручную на `main` в любой момент; публикация подписанного пакетного образа — отдельный флажок этого запуска. Включены Gitleaks, Bandit, CodeQL `security-extended`, pip-audit, actionlint, zizmor, проверки IaC, Hadolint, Trivy для Dockerfile/образа и регрессионные тесты на Python 3.11–3.13 и 3.15. Контейнер проходит запуск с локальной HTTPS-заглушкой модели; настоящие ключи LLM не требуются.

Общий статус `Security gate` требует успеха всех обязательных проверок, включая ошибки самих сканеров. Только после него создаётся artifact `verified-submission` со свежим ZIP. Его название означает прохождение перечисленных CI-проверок; совместимость с API организаторов и юридическая точность требуют отдельной оценки.

Области анализа, пороги, отчёты, ограничения и настройка проверок перед слиянием и перед выкладкой: [docs/security_pipeline.md](docs/security_pipeline.md).
