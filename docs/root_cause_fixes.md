# Исправление причин ошибок — 10 ноября 2026

Основание: предоставленный PSB_ponytail_audit_2026-11-10.md, F01–F09, и повторный реальный прогон до изменений: 14 PASS, 2 FAIL, 1 WARN, 1 технический сбой. Неверные утверждения о единственном способе изменения платы и сроке обнаружения всех недостатков имели настоящие цитаты. Причина — доверие к перефразированному выводу после вероятностного одобрения, а не отсутствие цитаты.

## Ограничения

Дословный текст источника может быть неверно выбран по дате, объекту или условию; механический барьер не доказывает полноту ответа и правильность применения нормы. Поэтому необходимы независимые семантические тесты и общий контроль качества/ложных отказов. Извлекательная выдача также может проигрывать краткому синтезу по удобству и полноте. Улучшение конкурсного Score не заявляется без нового сабмита.

Все синтетические документы находятся только в тестах. В runtime нет ответов на известные ID, новых правовых текстов или внешнего поиска. Сохранены модельные ограничения, таймауты, запрет перенаправлений, существование ID/точность цитат и лимит 10000 символов.

F09 остаётся открытым: инструменты GitHub позволяют читать настройки, но не изменять branch protection/rulesets. Требуется настроить обязательный Security gate на main в настройках репозитория. Этот PR позволяет CI проверить конкретные изменения, но не вводит административную защиту ветки.

Проверка воспроизведения: тот же новый набор из 13 тестов на прежних prototype-модулях даёт 10 FAIL; на исправленных — 13 PASS. В этом сравнении eval-модуль уже исправленный, поэтому оно не является повтором исходного внешнего аудита 28 тестов.

Проверка: python -m unittest discover -s tests -v (111 PASS); python audit_retrieval.py (32/32 положительных development-сценария); сборка ZIP, check_submission.py и check_dependencies.py. Реальный прогон новой версии сохраняется отдельно в results/deepseek_after_fixes_*; результаты прошлой версии не перезаписываются.

## Причины, уточнённые диагностикой

Отдельный повтор №16 на предфинальной версии дал отказ первого judge из-за склейки несмежных цитат. Во втором проходе та же модель уже одобрила их; это неустойчивость смысловой оценки, а не отсутствие источника. Финальная правка разделяет выдержки явно; отдельный повтор не подменяет исходный FALSE_REFUSAL.

Для публичного DeepSeek изучены официальные [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/) и [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/). По документации thinking включён по умолчанию (high), temperature в нём игнорируется, а finish_reason=length означает достижение лимита генерации/контекста. Наши прошлые temperature=0 — переданный параметр, не доказательство фактического детерминированного режима. Наблюдаемая обрезка зарегистрирована; точный состав потраченных токенов прежний журнал не сохраняет, поэтому расход на reasoning — объясняющая гипотеза, не доказанная телеметрия конкретного сбоя.

Проведён один изолированный эксперимент №5 с thinking.type=disabled через dev-адаптер, без изменения ZIP. Он занял 35.915 с, но вернул unverified: генератор требовал найти конкретный договор из пользовательского условия вместо применения общего регламента к гипотетическим сумме и дате; judge оба раза отверг такое уточнение. Этот эксперимент не подтверждает улучшение качества при отключении thinking. Настройки прокси организаторов не установлены.

Следующая корневая задача — явно разделять условные факты сценария пользователя и реквизиты найденного документа, с проверкой на разных суммах/датах. Простая замена температур, увеличение token cap или принудительное отключение thinking не объявляются исправлением этой ошибки.
