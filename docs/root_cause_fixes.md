# Исправление причин ошибок — 10 ноября 2026

Основание: предоставленный PSB_ponytail_audit_2026-11-10.md, F01–F09, и повторный реальный прогон до изменений: 14 PASS, 2 FAIL, 1 WARN, 1 технический сбой. Неверные утверждения о единственном способе изменения платы и сроке обнаружения всех недостатков имели настоящие цитаты. Причина — доверие к перефразированному выводу после вероятностного одобрения, а не отсутствие цитаты.

## Исправления

| Наблюдение | Причина | Изменение и проверка |
|---|---|---|
| Неподтверждённый пересказ проходит judge | Проверка наличия цитаты не доказывает смысл, а LLM может ошибиться повторно | Выдача произвольного пересказа заменяется точным процитированным текстом. Привязки и выбор применимости всё ещё проверяются моделью. Тесты с иными числами, выдуманной исключительностью и переносом срока на другое действие проверяют публикацию даже при положительном вердикте |
| F01 частичный ответ останавливает поиск | Любой approved означал завершение | Для частичного ответа с типизированным пробелом документа — один расширенный поиск. Уже проверенный partial сохраняется как запасной результат при ProviderError; неизвестная дата пользователя не вызывает бессмысленного поиска. Не более четырёх логических вызовов |
| F02 исчезают пункты 1–9 | Отбрасывались короткие токены и числовые вспомогательные признаки | Сохраняются цифры и точный структурный номер пункта; проверены пункты 1, 9, 23, 51 |
| Подсказки поиска привязаны к известным компаниям | Перечень имён и форматов номеров был вписан вручную | Имена извлекаются из кавычек в заголовочной части корпуса, номера договоров распознаются общей грамматикой. Сама грамматика остаётся ограничением, а не универсальным распознавателем |
| F03 ложный успех red-team oracle | Искомое число в цитате принималось за правильный вывод | Требуемый текст ищется отдельно от списка ссылок. Итог переименован в surface_checks_pass, semantic_status=NOT_REVIEWED. Даже успешная поверхностная проверка не является смысловым PASS |
| F04 длинное изменение теряет новое условие | Связанный документ иногда представлен только заголовком | Связанные по ID документы включаются полностью. Если 100000 символов/512 фрагментов не позволяют это сделать — явная ошибка, а не молчаливый выбор старого условия. Проверено изменение в конце документа с другими номерами и новым сроком |
| F05 пропадают сноски | Парсер читал только основной XML | DOCX со сносками/концевыми сносками или altChunk отклоняется явно. Полная поддержка сносок не заявляется; защита DTD сохранена |
| F06 пустой файл незаметен | Проверялась пустота корпуса целиком | Каждый файл проверяется на непустой текст; смешанная база с пустым документом отклоняется |
| F07 короткое значение нельзя процитировать | Строка отделена от контекста и меньше минимальной длины цитаты | Добавляются перекрывающие непрерывные диапазоны исходника с соседними строками; карантинные участки не пересекаются. Цитата по-прежнему точная |
| F08 конкретный пробел теряется | Разрешён свободный missing при пустом коде | partial/insufficient требует типизированный requested_facts либо допустимый issue; добавлен код referenced_documents. Непроверенный текст missing/clarification не публикуется |
| Неизвестна причина технического ответа | ProviderError превращался в общий текст без диагностического события | stderr сохраняет только ограниченный безопасный код ошибки. Ключи и тело ответа провайдера не журналируются. Причину старого сбоя задним числом установить нельзя |

Промежуточный реальный прогон выявил несогласованность: judge видел исходный черновик, хотя выдача использовала извлечённую цитату. Теперь candidate и rendered_answer согласованы до проверки; отдельный regression подтверждает, что discarded prose не влияет на вердикт. Промежуточная попытка сохранена отдельно от окончательной.

## Ограничения

Дословный текст источника может быть неверно выбран по дате, объекту или условию; механический барьер не доказывает полноту ответа и правильность применения нормы. Поэтому необходимы независимые семантические тесты и общий контроль качества/ложных отказов. Извлекательная выдача также может проигрывать краткому синтезу по удобству и полноте. Улучшение конкурсного Score не заявляется без нового сабмита.

Все синтетические документы находятся только в тестах. В runtime нет ответов на известные ID, новых правовых текстов или внешнего поиска. Сохранены модельные ограничения, таймауты, запрет перенаправлений, существование ID/точность цитат и лимит 10000 символов.

F09 остаётся открытым: инструменты GitHub позволяют читать настройки, но не изменять branch protection/rulesets. Требуется настроить обязательный Security gate на main в настройках репозитория. Этот PR позволяет CI проверить конкретные изменения, но не вводит административную защиту ветки.

Проверка: python -m unittest discover -s tests -v (110 PASS); python audit_retrieval.py (32/32 положительных development-сценария); сборка ZIP, check_submission.py и check_dependencies.py. Реальный прогон новой версии сохраняется отдельно в results/deepseek_after_fixes_*; результаты прошлой версии не перезаписываются.
