# Сохранение вводной нормы при выборе пункта перечня

База: main `696d77a0e0cdb31733c4c919b5fdc02e6efb24d4`, 10 ноября 2026.

## Причина

В демонстрационном вопросе о сезонной работе поиск уже передавал модели вводное предложение и нужный элемент перечня. Модель выбирала только элемент; проверяющий одобрял неполный текст. Полный абзац не обязательно является самостоятельной нормой. Поэтому расширение поиска без сохранения зависимости при публикации не устраняет этот класс потерь.

На исходном runtime шесть новых регрессионных методов: 3 FAIL, 0 ERROR. Неудачи сохранены в results/structural_before.txt. Синтетические документы содержат другие предметы, числа и запреты; производственный код не распознаёт номера демовопросов или их ответы.

## Изменение

Retriever строит узкие структурные связи из самого корпуса: вводный абзац с двоеточием → элементы плоского перечня с точкой с запятой и завершающей точкой. Поддержаны строчные продолжения и явные цифровые/буквенные/маркированные элементы. Смена оформления, новый вводный абзац, самостоятельный заголовок или карантин прекращают предыдущую связь.

Если поиск нашёл элемент, вводное положение добавляется в evidence с собственными координатами и ID. После выбора модели приложение дополняет источники утверждения обязательной вводной нормой. Проверяющий видит обе цитаты и именно публикуемый ответ. Подлинные тексты остаются отдельными цитатами: программа не сочиняет новое юридическое предложение.

Отсутствующая зависимость или превышение действующих лимитов приводит к явной технической ошибке; условие не отрезается ради публикации. Лимиты источников/контекста/ответа не увеличены. Дополнительных вызовов модели нет.

## Проверка

- 164 штатных теста PASS; 8 структурных регрессий входят в это число.
- Отдельные HTTPS harness tests: 5 PASS.
- 32/32 положительных сценария поиска на наборе разработки. Это не независимая оценка юридического качества.
- ZIP пересобран; шесть разрешённых корневых файлов совпадают с runtime; dependency gate PASS.
- ZIP SHA256: `ebd036874510430a1e1f5f3f115d89e17c65ba73ae4aa1c6129bf2e945f7bc53`, 21686 байт.
- Контроль №14 с заведомо одобряющей заглушкой: выбран один источник, проверены и опубликованы два — вводное положение и сезонное условие. Результат: results/structural_case14.json.
- Проверены соседние перечни, запрет/условие разрешения, разные маркеры, новый раздел, карантин, удалённая вводная норма за пределами соседнего поискового окна и ошибка при отсутствующей зависимости.

После реализации выполнен отдельный реальный прогон: 18 строк за 316,036 с, без технических и непроверенных ответов; 30/30 точных цитат. В №14 вводная норма сохранена. Полная ручная оценка, замечания к подаче и неудачная подготовка внешнего оценщика — в [отчёте прогона](structural_live_review.md). Предыдущие 17 PASS / 1 WARN относятся к ZIP `70ebed…` и не переназначаются новой сборке. Заглушка проверяет программную границу даже при ошибочном одобрении; она не оценивает выбор нормы реальной моделью.

## Границы и следующий эксперимент

Это синтаксическое распознавание ограниченного вида плоских перечней, не универсальный парсер юридической структуры. Вложенные списки, таблицы, внешние исключения, произвольные заголовки и изменения норм требуют отдельных отношений и проверок. Наличие вводной нормы не доказывает применимость и полноту ответа. Неоднозначное оформление может не распознаться; область поддержки нельзя считать всей базой.

Регрессии уже использованы при разработке и не являются слепым контрольным набором. Следующий этап — независимая разметка комплектов оснований и измерение ошибочных одобрений/отказов проверяющего. Другой API может использоваться как внешний оценщик разработки; конкурсный runtime сохраняет API организаторов. Гибридный поиск и реранкер следует проверять после установления конкретных потерь retrieval.
