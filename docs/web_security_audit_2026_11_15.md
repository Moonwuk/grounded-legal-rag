## Подтверждённые проблемы и исправления

1. **Уязвимые зависимости образа.** Trivy 0.76.2 обнаружил семь записей
   исправляемых HIGH/CRITICAL в исходном рабочем образе: две для zlib, две для
   msgpack, одну для setuptools и две для urllib3. Последние библиотеки находились
   во встроенных компонентах pip; в `web/requirements.txt` pip-audit находок не дал.
   Обновлена zlib до `1:1.3.dfsg+really1.3.1-1+deb13u1`, базовый образ закреплён
   digest, pip/setuptools/wheel удалены после установки runtime-зависимостей.
   Повторный скан: **0 исправляемых HIGH/CRITICAL**, секретов в образе — **0**.
   Это результат на дату сканирования, не отсутствие всех CVE или будущих проблем.
2. **Защита API зависела от внешнего прокси.** При настроенной истории
   `/api/documents` и stateless `/api/chat` принимали запросы без токена прокси
   через локальный порт. Публичный прокси их уже защищал; обход с интернета не
   продемонстрирован. Теперь все `/api/*` требуют проверенной пары логин/токен
   при включённой серверной истории. Чужие объекты дополнительно проверяют владельца.
3. **Отсутствовали CSP и запрет framing.** Добавлены CSP, `frame-ancestors 'none'`,
   `X-Frame-Options: DENY`, nosniff, Referrer-Policy и Permissions-Policy. Скрипты
   и соединения разрешены только с того же origin. Inline-стили разрешены для
   существующего интерфейса; inline-скрипты и eval не разрешены. HTML в названиях,
   вопросах и ответах отображается текстом; проверено в Chromium.
4. **Не было явной проверки происхождения изменений.** Для изменяющих API-запросов
   добавлены проверка Origin и отказ при `Sec-Fetch-Site: cross-site`. `null` и
   некорректные Origin отклоняются. Запросы серверных клиентов без Origin допускаются
   с действующей авторизацией. Прокси должен сохранять Host и заменять заголовки
   идентификации, а не доверять присланным клиентом значениям.
5. **Не было общего бюджета генерации на логин.** Теперь оба API используют общие
   SQLite-счётчики: 30 запросов/минуту и 300/сутки по умолчанию. Они не исчезают при
   удалении диалога или перезапуске; повтор принятого job ID не расходует квоту.
   Превышение возвращает 429 и Retry-After. Окна фиксированные, границы UTC;
   квота ограничивает принятые вопросы, а не точную сумму денег или число токенов.
6. **Не были ограничены ресурсы веб-контейнера и его журналы.** Добавлены 2 GiB,
   2 CPU, 128 PID и ротация 3 × 10 MiB. Сохранены non-root, read-only root,
   cap-drop ALL, no-new-privileges, localhost-порт и отдельный том истории.
7. **Права конфигурации демо-прокси.** Приватный Caddyfile, содержащий секрет
   связи с приложением, имел 0644. Установлены 0600; `.env` и файл доступа уже 0600.
   Значения секретов, пароли и пользовательские сообщения в отчёт не включались.

## Автоматические проверки безопасности

Последний полный `Security scans` в main на момент аудита — run `43712229335`,
SHA `891abf3` — **failure**. Успешный Web CI ранее не означал успех этого gate.
Разобраны причины:

- CodeQL не мог читать metadata workflow run: добавлено только необходимое
  разрешение `actions: read` в его job. Полный запуск CodeQL этой ветки не заявляется:
  workflow настроен на main; требуется повтор после попадания исправления в main.
- TLS smoke ожидал два вызова, хотя batch по умолчанию использует один. В тестовой
  среде явно включён `PSB_VERIFY=1`, чтобы по-прежнему проверять генерацию и
  верификацию. Все пять тестов fixture проходят; production batch не изменён.
- Валидатор Trivy secret-report не принимал наблюдаемый инвентарь Debian.
  Добавлен только этот тип при сохранении строгой проверки структуры и находок.
  Проверки положительного/отрицательного формата и реальный secret-scan проходят.
- Zizmor 1.32 рекомендует новый синтаксис self-repository, а закреплённый actionlint
  1.7.12 этот синтаксис не принимает. **Совместимость инструментов остаётся открытой**;
  правило не подавлено, порог gate не ослаблен. Полный Security gate пока нельзя
  назвать зелёным. Требуется согласованное обновление инструментов/поддерживаемого
  синтаксиса, а не отключение проверки.

Web CI теперь выполняет полный scan веб-образа на каждом PR. Периодический
Bandit расширен на production-код `web/`; тесты исключены. Локальные результаты:
425 core-тестов, 45 web-тестов, 13 frontend-тестов; пять TLS fixture-тестов;
pip-audit требований веба без известных находок; Bandit без находок; actionlint
проходит с сохранённым синтаксисом workflow. Сканирование образа включает
положительный preflight секретного детектора; сырой отчёт не публикуется.

## Дополнительно для LLM

Документы и ответы модели считаются недоверенными; API-ключ не передаётся в
промпт. У модели нет инструментов записи в базу, shell или произвольного браузинга.
URL провайдера задаёт оператор, а не пользователь; редиректы провайдера запрещены.
Квоты, semaphore и таймауты ограничивают потребление. Но остаются риски ложных
юридических выводов, неизвестных prompt injection, отравленного исходного корпуса
и расхода денег провайдером после закрытия HTTP-запроса. Проверка цитаты не равна
проверке правового смысла. Нужны отдельные adversarial/юридические сценарии и
денежный лимит в аккаунте провайдера перед реальным использованием.
