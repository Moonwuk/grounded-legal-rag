# Работа с ответами и компактная компоновка

Реализация: `web/static/app.js`, `index.html`, `usability.css`, `web/history.py`, `web/app.py`.

- Источники сгруппированы по документу. Каждая выдержка сохраняет номер, точный текст и переход к собственному диапазону. Превью визуально обрезается CSS, полный текст доступен через раскрытие и копирование.
- Копирование включает ответ, названия, разделы и полные цитаты. При отказе Clipboard API открывается собственное окно с выделяемым текстом.
- Печать / PDF формирует отдельное представление всех загруженных сообщений текущего диалога, включая источники. В PDF нет панелей, анимации или ограничений высоты прокрутки. Используется системная печать браузера, сохранение файла выбирает пользователь. Обработчик `beforeprint` заново собирает текущий диалог и для Ctrl+P / меню браузера.
- Поля уточнения строятся только из фиксированного словаря `FOLLOWUPS`, присутствующего в опубликованном тексте. Для старой истории без метаданных есть общее поле. Кнопка отправляет сведения через обычную очередь; существующий черновик заменяется после собственного окна подтверждения.
- `GET /api/chats?q=...` ищет по названию, вопросам и текстам ответов без учёта регистра. Предел — 200 символов запроса. Поиск производится после проверки владельца и выбора активных/удалённых диалогов; полные тексты не возвращаются в списке. Фронтенд отбрасывает запоздавшие результаты.
- `PUT /api/chats/{id}/pin?pinned=true|false` сохраняет закрепление. Нужны аутентифицированный владелец и Content-Type JSON. Добавление столбца `pinned` в SQLite не удаляет историю. Закреплённые идут первыми, внутри групп — по времени.
- Поиск в документе использует буквальную строку (не пользовательское регулярное выражение), сохраняет исходный текст, подсвечивает до 500 совпадений. Цитата отдельно проверяется по кодовым точкам Unicode; поиск работает по индексам JavaScript, диапазоны пересекаются без изменения текста. «К цитате» возвращает к исходному основанию, даже после поиска. На коротком мобильном экране текст прокручивается отдельно от поиска, а переход использует фактический видимый диапазон элемента.
- На компьютере шапка компактна, панель документов сворачивается. На телефоне доступен новый диалог из основной шапки; история показывает короткие строки с меню `⋯`, папки раскрываются отдельно. Пустой селектор пользовательских вкладок скрыт, повторного заголовка каталога нет.
- В форме вкладки прокручивается только центральная область. Заголовок и Сохранить / Отмена остаются видимыми; дополнительные фильтры на телефоне раскрываются по запросу.

## Проверки

`python3 -m unittest discover -s web/tests -v` проверяет изоляцию поиска и закреплений, сохранность истории и допустимые поля уточнения; `node --test web/tests/archive-scene.test.cjs` — восстановление ответов, источников и историю ошибок.

Браузерный сценарий `web/browser-tests/usability.cjs` выполняется через Playwright против локального приложения **без настроенной истории** (чтение реального корпуса, запись диалогов перехватывается фикстурами). Проверяет копирование, печать/PDF, точные цитаты, поиск, отправку уточнения, закрепление и геометрию на 1440×1000, 390×844, 320×568 и 390×420. `AUDIT_OUTPUT` задаёт папку скриншотов и тестового PDF, по умолчанию `/tmp/legal-usability`.

```bash
NODE_PATH=/path/to/playwright/node_modules \
CHROMIUM_PATH=/path/to/chrome BASE_URL=http://127.0.0.1:8003 \
node web/browser-tests/usability.cjs
```

Папки, корзина, переименование и очередь дополнительно проверяются соответствующими сценариями из `web/browser-tests/` на изолированном сервере `queue_fixture.py`. Его ответы — заглушки, не оценка юридического качества модели. Скриншоты в уменьшенном viewport не заменяют проверку экранной клавиатуры на физическом телефоне или полный аудит доступности.
