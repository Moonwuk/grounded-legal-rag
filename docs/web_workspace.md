# Рабочие материалы в веб-интерфейсе

Реализация: `web/workspace.py`, `web/static/workspace.js`, `web/static/workspace.css`. Модуль подключён к FastAPI и к существующей SQLite истории. Ядро `prototype/`, промпты, поиск, проверка ответов, генерация в очереди и контракт `/api/chat` сохранены.

## Возможности

- **Карточка дела** хранит договор, контрагента, дату события, сумму и рабочие обстоятельства. Эти сведения не добавляются в контекст модели автоматически. Кнопка «Добавить в вопрос» явно вставляет заполненные поля в видимый черновик; отправку выполняет пользователь.
- **Избранное и заметки** сохраняют конкретный ответ вместе с его существующими источниками. Личная заметка отображается отдельно и не становится юридическим основанием. В панели истории доступны поиск и фильтры: всё сохранённое, избранные ответы, ответы с заметками.
- **Черновики** сохраняются на сервере отдельно для каждого диалога и для ещё не созданного диалога. После изменения поля сохранение начинается через 600 мс; индикатор сообщает об успехе только после ответа сервера. При переключении диалога ожидается сохранение. Ошибка связи показывается явно; мгновенное закрытие браузера до окончания записи может оставить несохранённый текст.
- **Два устройства** используют номера ревизий. Устаревшая запись не заменяет свежую: для черновика открывается окно с обеими версиями и явным выбором. Конфликт карточки или заметки сохраняет введённый текст в форме и требует загрузить свежие данные перед повторной записью.
- **Изменить вопрос** создаёт новый диалог с историей до выбранного вопроса и исправленным текстом в черновике. «Продолжить в ветке» включает также выбранный ответ. Последующие сообщения не копируются. Исходный диалог остаётся целым; карточка дела и папка наследуются, заметки и отметки избранного — нет. Создание ветки не вызывает модель. Ветка имеет ссылку на исходный диалог, пока тот доступен.
- **Вопрос по выделенному фрагменту** добавляет название документа, точный выбранный текст и вопрос в поле ввода. Пользователь видит весь отправляемый текст. Поиск продолжает работать по всему корпусу, включая связанные положения и исключения.
- **Документы рядом** показывают два полных извлечённых текста с независимой прокруткой. На узком экране переключаются первый и второй документ. Из ответа с несколькими документами можно сразу открыть первые два источника рядом. Это просмотр для самостоятельного сопоставления, без автоматического юридического сравнения и вывода о действовавшей редакции.
- **Редактирование очереди** доступно только ожидающему вопросу, сохраняет его идентификатор и место. Если обработчик уже забрал вопрос или другое устройство изменило текст, сервер отклоняет устаревшую правку. Новая квота за редактирование не списывается.
- **Новый ответ** отмечается у другого диалога. Прочтение синхронизируется по логину. Фоновая проверка активности выполняется раз в 8 секунд на видимой странице. Позиция чтения документа сохраняется в этом браузере; переход к цитате имеет приоритет над восстановлением позиции.

## Данные и границы

Таблицы `chat_workspace`, `new_dialogue_drafts`, `answer_annotations` создаются добавочной миграцией. Текст старых диалогов не переписывается. Все операции проверяют пользователя через существующий авторизующий прокси, используют параметризованный SQL и общую защиту от запросов с другого сайта. Ответы API имеют `private, no-store`.

Аннотация привязана к индексу и хешу всего сохранённого вопроса/ответа. Устаревшая аннотация не переносится на заменённый результат. В избранном нет диалогов из корзины; восстановление возвращает их заметки. Окончательное удаление диалога каскадно удаляет его рабочие данные, но сохраняет самостоятельные ветки без ссылки на удалённого родителя.

Пределы: черновик/вопрос — 10 000 символов, заметка к ответу — 4000, обстоятельства — 3000, договор и контрагент — по 300. Сохраняются прежние лимиты 100 активных диалогов и 20 вопросов в диалоге. JSON ограничен 128 KiB. Ветки создаются с идемпотентным идентификатором, поэтому повтор после потери ответа не создаёт дубликат.

## Оформление и состояния

Новые элементы используют цвета и шрифты из настроек оформления. Знакомые действия обозначены SVG-иконками с `aria-label` и подсказкой; смысловые команды и подтверждения сохраняют текст. Область нажатия иконки на сенсорном устройстве — минимум 44×44 px. Favicon — локальный `web/static/favicon.svg`.

История показывает кадр каждого состояния ассистента. Новое завершение в очереди проигрывает соответствующую реакцию один раз. Раньше восстановление истории добавляло персонажа только для `clarify`, поэтому остальные реакции исчезали после завершения фонового задания. Исправление использует тот же `ArchiveScene.stateFor`, что и прямой ответ. `cancelled` имеет отдельную остановленную позу. Отключение анимаций и системное уменьшение движения соблюдаются; юридические статусы не меняются.

## Проверки

```bash
python3 -m unittest discover -s web/tests -v
node --test web/tests/archive-scene.test.cjs
```

`web/tests/test_workspace.py` проверяет изоляцию пользователей, ревизии, миграцию, корзину и удаление, идемпотентные ветки, границы текста и редактирование очереди. Проверка с заглушкой генерации подтверждает отсутствие карточки и заметок в контексте модели и отсутствие будущих сообщений в ветке.

Для браузерной проверки нужен **отдельный локальный сервер с временной SQLite и заглушкой модели** `web/browser-tests/queue_fixture.py`. Передайте ему `CHAT_HISTORY_PATH`, `CHAT_PROXY_TOKEN=fixture-token` и `PYTHONPATH` корня репозитория; при запуске в Docker публикуйте его порт только на `127.0.0.1`. Сценарий использует тестовый логин `workspace-browser`, создаёт диалоги и оставляет их в одноразовой базе. На рабочем демо его запускать нельзя.

```bash
NODE_PATH=/path/to/playwright/node_modules \
CHROMIUM_PATH=/path/to/chrome BASE_URL=http://127.0.0.1:8003 \
WEB_FIXTURE_CONFIRMED=1 AUDIT_OUTPUT=/tmp/workspace-review \
node web/browser-tests/workspace.cjs
```

Проверяются два браузерных контекста, конфликт черновиков, неизменность исходной истории, избранное и заметки с XSS-строкой, выделение фрагмента без автоматической отправки, полные тексты документов, очередь, отметка нового ответа, тёмная тема и Inter 22 px на 1440×1000, 390×844, 320×568 и 390×420. Это проверки веба с заглушкой, не оценка юридического качества. Экранная клавиатура физического телефона и полный аудит экранным диктором отдельно не заявляются.

`web/browser-tests/animation-states.cjs` проверяет восстановленные позы, разовое проигрывание нового ответа очереди, отключение и уменьшение движения, доступные названия иконок и загрузку SVG favicon. Ответы в этом сценарии перехватываются браузерными фикстурами; серверная история не изменяется.
