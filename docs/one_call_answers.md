# Один вызов модели на ответ в batch

Изменение от 13 ноября 2026. Код: `psb_policy.answer_steps(..., verify=False)`,
`solution.run_questions`, переменная `PSB_VERIFY`. Регрессии —
[tests/test_one_call_answers.py](../tests/test_one_call_answers.py).

## Симптом и подтверждённая причина

| Архив | Схема | Балл платформы | Время |
|---|---|---|---|
| 6 версий до 13.11 | генерация + проверяющий вызов + повторы, 2–5 вызовов на вопрос | 20,0–23,9 | 694–1130 с |
| №12 `PSB_12_one_call.zip` | тот же код, один вызов на вопрос | 34,2 | 507 с |
| №13 пример организаторов без изменений | один вызов, без проверок | 10,2 | 347 с |

Прогоны с проверяющим вызовом заканчивались на внутреннем дедлайне 1100 с:
строки, до которых очередь не дошла, оставались техническими заглушками
(оценка судьи около 0). Тот же код без проверяющего вызова уложился в половину
бюджета и получил на 10–14 баллов больше. Число вопросов платформы не раскрыто;
публичный репозиторий другой команды оценивает время на 300 вопросов.
Пример организаторов набрал 10,2, значит baseline судьи — не он.

## Поведение

В batch по умолчанию (`PSB_VERIFY` не равен `1`) ответ — одна генерация. Её
текст публикуется только после программных проверок: числа, даты и номера
пунктов есть в выбранных положениях, фактах пользователя или явно записанном
расчёте; барьеры добавленных утверждений, ложного «в базе нет» и выдуманных
разделов; сохранение классов ограничений
([contrast_and_restricted_answers.md](contrast_and_restricted_answers.md));
редакция на дату события. Если проверка отклоняет текст или выбранная
редакция не действовала на дату события, строка сохраняет дословные положения,
а ещё одна генерация получает код причины. Частичный ответ с недостающим
документом получает одно расширение поиска (правило 3 AGENTS). Повторы batch
выполняет после первого ответа каждой строки. Предел — две генерации на ответ
(три при отказе первой без источников), общий лимит вызовов прежний.

`PSB_VERIFY=1` возвращает прежнюю схему с проверяющим вызовом. Веб-чат и
`answer_structured`/`answer_question` по умолчанию её сохраняют: у них нет
общего дедлайна на сотни вопросов.

## Что теряется и что не проверено

Отдельный проверяющий вызов ловил смысловые ошибки, которые программные
проверки не видят: неверный вывод при верных числах, неприменимое положение
другого договора, неполный перечень условий. Кейс требует контроля
достоверности; отдельный LLM-верификатор в нём назван вариантом реализации.
На 24 диагностических вопросах и демо организаторов (наборы уже использовались
для настройки) выдуманных фактов при ручной сверке с базой не найдено; это не
доказательство для скрытого набора. Балл платформы этой версии (№14) на момент
изменения неизвестен.
