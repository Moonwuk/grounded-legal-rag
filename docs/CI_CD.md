# CI и обновление Windows

PR в main проверяется GitHub-hosted runner. Web CI проверяет импорты и Python HTTP-тесты, JS, разбор PowerShell, конфигурацию Compose, сборку и HTTP. Web CI также запускает тесты ядра и независимых валидаторов. Security scans проверяет зависимости, секреты, Bandit, CodeQL, IaC и пакетный контейнер на main раз в два дня. Проверки используют заглушки или локальный health endpoint и не запускают платный benchmark.

Владельцу репозитория нужно открыть Settings → Rules → Rulesets и создать активный ruleset для refs/heads/main. Включить обязательный PR, минимум одно независимое одобрение, сброс устаревших одобрений, проверку свежего push и обязательные проверки Web tests and container и матрицу RAG regression. Если Security gate был обязательным для PR, удалите его из этого списка. Указать GitHub Actions источником этих проверок, включить strict/up-to-date, отключить bypass, force push и удаление main. Имена выбираются из последних фактических запусков; конкретное отображение зависит от интерфейса GitHub. Merge через GitHub должен создавать SHA, связанный с PR. Ручной push не пройдёт локальный фильтр публикации. Права текущего аккаунта не позволяют настроить ruleset.

После merge агент (update.ps1 на Windows, deployment/linux/psb-deploy.sh на Linux) проверяет официальный main, связь SHA с merged PR, успешный push-запуск web-ci.yml и успешный Security gate в запланированном запуске для этого же SHA и, при политике `Required` (по умолчанию), актуальное одобрение другого участника. При политике `CiOnly` одобрение не требуется. До подтверждения сайт продолжает работать на прежнем образе; причина ожидания видна в status и deployment.log. Web CI также проверяет Linux-агент: shellcheck и сценарии на заглушках. Аккаунту агента нужны права чтения через gh CLI, токен хранится в штатном хранилище клиента. Компоненты deployment копируются в стабильную директорию при установке. После слияния изменения расписания обновите установленные агенты Windows и Linux из проверенной версии. Прежний агент ищет Security scans по событию push. Новый агент пропускает дни без сканирования и ждёт подходящего запуска для текущего SHA. Laptop не регистрируется self-hosted runner.
