# Конкурсное ядро в веб-чате

По умолчанию `WEB_CORE=experiment`: вопросы обрабатываются конвейером из
`submissions/psb_experiment/`. Исходники конкурсного ядра и его ZIP при подключении
не изменяются. `WEB_CORE=prototype` возвращает предыдущий веб-конвейер.

## Путь запроса

`web/app.py` проверяет запрос, авторизацию и квоты. `web/generation.py` запускает
отдельный процесс с лимитом 180 секунд; остановка закрывает процесс вместе с
соединением к модели. Одинаковый обработчик используется очередью и `/api/chat`.

`web/experiment.py` передаёт ядру документы, прочитанные защищённым загрузчиком
`prototype/psb_corpus.py`: сохраняются ограничения ZIP, XML, размера и карантина.
В дочернем процессе временно заменяется только вход загрузчика `load_raw_docs`;
разбиение, поиск, промпты и генерация выполняются конкурсными модулями.
Глобальное состояние ядра не переносится между вопросами или пользователями.
История передаётся явно из текущего диалога.

Каталог продолжает использовать SHA-256 исходных файлов. Адаптер переводит позиции
цитат из очищенного текста ядра в координаты оригинала, учитывая CRLF, неразрывные
пробелы и удалённые инструкции. Существующие ссылки, подборки и старые диалоги
сохраняют свои идентификаторы. Цитата проверяется на точное совпадение и пересечение
с карантином; некорректный диапазон не публикуется.

Ошибки ядра, неподтверждённые суммы, несуществующие ссылки и ответы без источников
получают технический статус и возможность повтора. Черновики и диагностический
текст модели не передаются в браузер или серверные журналы. Проверка ссылок не
является доказательством юридической правильности вывода. Отдельный LLM-верификатор
старого `prototype` к новому конвейеру не добавляется.

## Настройки

- `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` задают существующий провайдер генерации.
- `WEB_CORE=experiment` выбирает новое ядро, `prototype` — прежнее.
- Пустой `EMB_MODEL` сохраняет BM25. При заданной модели каждый изолированный запрос
  проверяет готовые векторы корпуса через API; при несовпадении пробует построить
  индекс в пределах 30 секунд, затем использует BM25 при неудаче.
- Пустой `RERANKER_MODEL` отключает реранкер. Заданное имя использует тот же прокси
  и его ключ. Публичный провайдер генерации не обязательно поддерживает эти API.
- `MAX_TOKENS`, `TEMPERATURE` и `TOP_K` передаются настройкам конкурсного ядра.
  `LLM_REASONING_EFFORT` и `PSB_DENSE_SECONDS` относятся к режиму `prototype`.
- `/healthz` возвращает `core: experiment` или `core: prototype`. Поле `fragments`
  относится к каталогу защищённого загрузчика; поиск нового ядра нарезает текст
  самостоятельно. При экспериментальном ядре `dense: off` описывает отсутствие
  общего фонового индекса, а не исход индексации отдельного запроса.

## Проверки и обновление

`web/tests/test_experiment.py` проверяет реальный конкурсный конвейер с заглушкой
HTTP API: ответ и исходные диапазоны, отклонение выдуманных сумм и пунктов, сохранение
ответа очередью. Проверка остановки процесса находится в `web/tests/test_queue.py`.
Остальные тесты веба проверяют историю, изоляцию пользователей, квоты и интерфейс.

Перед выкладкой нужны успешные Web CI и Security gate, копия SQLite и предыдущий
образ. После пересоздания контейнера проверьте `/healthz`, старые диалоги, новый
вопрос, открытие цитаты, остановку и продолжение очереди. Откат: прежний образ либо
`WEB_CORE=prototype` с пересозданием контейнера; схема истории не меняется.

Живые проверки публичного DeepSeek подтверждают работу интеграции. Они не являются
повторным конкурсным прогоном и не подтверждают балл скрытой выборки.
