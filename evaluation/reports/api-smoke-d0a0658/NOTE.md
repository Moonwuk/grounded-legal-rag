# Прогон с неверной настройкой стенда

Smoke 12 вопросов synthetic, `deepseek-flash` через публичный API DeepSeek
(не модель платформы), стенд на коммите `d0a0658`, 2026-11-10.
Ответы решения этим прогоном почти не измерены: 9 из 12 — `system_error`.

| Исход | Кейсы | Причина |
|---|---:|---|
| `truncated_model_output` | 7 | Дефект стенда: `config.json` задавал `max_tokens: 2048`, а runtime по умолчанию использует 8192; модель с рассуждением выдавала ровно 2048 токенов |
| `evidence_size_limit` | 2 | Поведение production-поиска на плотном синтетическом корпусе: связанные по номеру объекта документы дают контекст больше 100 000 символов. Оба кейса — security; защита не проверена |
| `benchmark_budget_exhausted` | 1 | Дефект стенда: лимит токенов считался по байтам UTF-8 (2,94 из 3 млн), реально ~0,52 млн входных токенов |
| ответ получен | 3 | `missing_information-0001` PASS; `fact-0001` not_evaluated (текст модели вне грамматики); `fact-0000` FAIL — ложное отклонение: соседняя строка восстановленной таблицы засчитана как утверждение |

`validator_false_acceptance_rate 0/7` и `validator_false_rejection_rate 0/4` в
`summary.json` взяты из устаревшего `reports/validator_calibration.json`
(b5ecfdc), а не из валидатора этого коммита. `end_to_end_success 1/1` имеет
знаменатель в один кейс.

Вызовы: 30 к модели + 2 probe; ~523,6 тыс. входных и ~43,1 тыс. выходных токенов.
Подробные ответы по кейсам (`cases/`) в Git не включены.
Исправления стенда и повторный прогон — см. [PR_STATUS](../../PR_STATUS.md).
