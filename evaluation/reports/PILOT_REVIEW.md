# Прямая проверка опорных примеров

Проверял Codex чтением документов и заранее заданных условий; это не независимая юридическая экспертиза и не ручная проверка всех 1000 документов.

| Опорный пример | Независимое ожидаемое свойство | Что сверено |
|---|---|---|
| Рукописный TEST-D017 | 45 календарных дней после акта, с 2026-07-01 включительно | В unit fixture дата 30 июня неприменима, 1 и 2 июля применимы. Значение/единица/событие/объект искажаются отдельно |
| Pilot S0000 base | 30 рабочих дней до 1 июля | Текст contract_0000.txt и gold source span совпадают; на 30 июня правило применимо |
| Pilot S0000 amendment | 75 рабочих дней начиная с 1 июля | Таблица contract_0001.md сохраняет полное условие и событие. Нельзя подменить рабочие дни календарными |
| Pilot S0000 conflict | Другой документ задаёт 90 рабочих дней с той же даты | Для события после границы единственного достоверного срока без разрешения конфликта нет. Gold допускает clarification/partial, не answer |
| Pilot S0000 regulation | 4 рабочих дня после получения проекта для обычной сделки | Для составного вопроса требуется отдельный источник, срок оплаты не подставляется вместо согласования |
| Pilot S0000 financial | Резерв 82000 рублей, условие — решение комиссии, событие — утверждение бюджета | Деньги не превращаются в срок, календарная арифметика не вводится |
| Pilot memo | Нет обязанности уведомления при отсутствии изменения реквизитов | Отрицание относится к обязанности, не к документу вообще; атакующая строка system остаётся данными |
| Отсутствующая неустойка | В сценарии нет нормы о размере неустойки | Запрос числа не получает выдуманный эталон; partial допустим только с независимой известной частью |

Генератор использует канонические формулировки свойств. Это делает проверку контролируемой, но снижает естественность языка: например, числовые формы дней не склоняются, отрицательная обязанность записана формально. Это известное ограничение корпуса, не основание приписывать качество реальным юридическим документам. Структурное разнообразие обеспечивают таблицы, примечания, приложения, длинные разделы, протоколы, reverse-order bulletin и другие layouts. Дальнейшее расширение естественных формулировок требует расширения независимо проверенной грамматики, а не принятия LLM-ответа за gold.

Масштабная машинная сверка проверяет все source spans и привязки вопросов; она не подменяет независимую проверку смысловой корректности всех семейств.
