Ветка создана от `main` **90c51e2b3450c8a34215a210e93f1ea98f234be2**.
Переносится ранее подготовленный независимый стенд, исходные измерения которого
выполнены на **b5ecfdc130c8f10aacd75a2d813b124f01e923c3**. Старые отчёты,

Они не описывают нынешнюю архитектуру и не подтверждают нынешнюю точность.

## Уже известные ограничения интеграции

В текущем main есть [независимый replay](../docs/external_evaluation_replay.md),
добавленный [PR #13](https://github.com/Moonwuk/grounded-legal-rag/pull/13).
Он устанавливает следующие несовместимости переносимого стенда:

1. `adapters/worker.py:TracedRetriever` не передаёт новые методы/атрибуты
   `documents`, `reference_gaps`, `complete_sources`. Наблюдение может менять
   результат production policy. До оценки ответов нужна прозрачная обёртка
   и проверка равенства прямого и обёрнутого вызова.
2. `validators/core.py:validate` проверяет `claims`, но равенство
   `rendered_answer == answer` не доказывает корректность нового связного
   `candidate.answer`. В main сохранён отрицательный пример ложного PASS.
   Для неподдержанного видимого prose нужен как минимум `not_evaluated`;
   необходима отрицательная регрессия по самому опубликованному тексту.
3. Worker берёт цитируемые фрагменты из исходного списка loader, тогда как
   новый Retriever может возвращать восстановленные блоки с другими ID.
   Адреса источников нужно получать из фактически принятого evidence.

Эти дефекты не объявляются исправленными в этом PR. До их устранения
**не использовать answer/end-to-end метрики стенда для оценки текущего main**.
Зелёные собственные unit-тесты сами по себе не доказывают такую совместимость.
Для текущего поиска предпочтителен уже имеющийся
`eval/replay_external_retrieval.py` с `--evaluation-root evaluation`.

В отчётах replay main старые 45 исключений TOP_K=6 уже не воспроизводятся:
synthetic/mixed — 394/394 достаточных контекстов, public — 20/20. Это результаты
существующего upstream replay, а не новый API-прогон этой ветки. Старые числа
45 и 0/7/27 в FINAL_REPORT относятся только к b5ecfdc. Рост TOP_K по-прежнему
требует отдельного измерения. Новых внешних вызовов DeepSeek при создании PR нет.

## Состав Git-изменений

Включены код, настройки, formal specs, 1000 synthetic docs /500 вопросов,
135 public docs с лицензиями, mixed1135, отдельные gold/questions, сводные
отчёты, журналы unit-тестов и воспроизводимый 60-document archive.

Не включены около 1 GiB подробных case observations, пересобираемые JSON
индексы и SQLite checkpoints. Они сохранены в исходной локальной рабочей
копии и ранее подготовленном ZIP. Новые прогоны создают их заново; команды
описаны в [README](README.md). Реестры источников и лицензии остаются в Git.

Изменения runtime, конкурсной базы и сабмита в эту ветку не входят.
Корневые README/AGENTS обновлены только для навигации к новой подсистеме.
Для воспроизведения первоначального FINAL_REPORT нужен отдельный checkout
b5ecfdc; для проверки текущего main использовать upstream replay и сохранять
новый source SHA/новые результаты отдельно.
