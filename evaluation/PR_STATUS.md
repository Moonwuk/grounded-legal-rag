## Несовместимости с текущим main и их исправление

[Независимый replay](../docs/external_evaluation_replay.md) из
[PR #13](https://github.com/Moonwuk/grounded-legal-rag/pull/13) установил три
несовместимости переносимого стенда. Исправлены в этой ветке; каждая
воспроизведена регрессией, которая падает на прежнем коде и проходит после
исправления ([test_observation_fidelity.py](validator_tests/test_observation_fidelity.py)).

| Симптом | Первопричина | Исправление | Проверка |
|---|---|---|---|
| Под наблюдением `answer` превращался в `partial` с требованием уже имеющегося документа | `adapters/worker.py:TracedRetriever` отдавал только `search`/`evidence`; policy включает учёт структуры, отсылок и документов через `hasattr`/`getattr` | Обёртка записывает только `search`, остальные члены `Retriever` передаёт без изменений | Все публичные члены доступны; `answer_question` напрямую и через обёртку даёт одинаковый текст и статус на двух вариантах с разными документами, числами и номерами |
| Подменённый видимый ответ при настоящих цитатах получал PASS | `validators/core.py:validate` проверял `claims` и равенство `rendered_answer == answer`, но не сам текст модели `candidate.answer` | `prose_check`: текст в пределах грамматики сверяется с эталоном (FAIL при неверном факте), иначе `published_prose_semantics` → `not_evaluated`. Опубликованный текст должен начинаться с проверенного prose; ответ без prose должен содержать все цитируемые положения | Мутация из `results/external_evaluation_false_acceptance.json` больше не проходит; неверные числа, единица и объект в prose дают FAIL; корректный prose проходит |
| Подлинные цитаты могли считаться `citation_failure` | Worker искал цитируемые ID в списке загрузчика, а `search` выдаёт восстановленные блоки с новыми ID | `cited_fragments` берёт адреса из фрагментов, фактически переданных policy; ненайденный ID → `unobserved_citations` и `adapter_unobserved_citation` (`not_evaluated`, а не ошибка решения) | Через `worker.main` со сценарной моделью: цитируются ID, которых нет у загрузчика, и все они возвращаются с точными диапазонами исходника |

Калибровка валидатора (`test_validators.py:calibration`) расширена мутациями
опубликованного текста: 0 из 11 повреждённых ответов получают PASS, 0 из 6
допустимых — FAIL. Это конечный набор, а не доказательство полноты обнаружения.
Тесты стенда запускаются в CI в задании `regression`, входящем в `Security gate`.

### Что остаётся ограничением

- Все проверки выше используют сценарную модель-заглушку. Реальных вызовов
  DeepSeek и платформенной модели не было; качество ответов не измерено.
- Грамматика валидатора узкая. Связный текст реальной модели вне неё получит
  `not_evaluated`: это честная граница, но для калибровки ответов в режиме
  prose понадобится расширение грамматики или ручная проверка таких кейсов.
- Если VERIFY отклонил prose и решение опубликовало только положения, worker
  не связывает новый текст с кандидатом; кейс остаётся `not_evaluated`.
- Синтетические документы написаны одной формулой и не используют имена
  `документы компании__`/`законы__`; логика законов на них не проверяется.
  Корпус в формате раздела 14 (`data/questions.csv` + `gold/cases.json`)
  не создан.
- Старые отчёты и `reports/validator_calibration.json` относятся к b5ecfdc и
  не пересчитывались.

В отчётах replay main старые 45 исключений TOP_K=6 уже не воспроизводятся:
synthetic/mixed — 394/394 достаточных контекстов, public — 20/20. Это результаты
существующего upstream replay, а не новый API-прогон этой ветки. Старые числа
45 и 0/7/27 в FINAL_REPORT относятся только к b5ecfdc. Рост TOP_K по-прежнему
требует отдельного измерения. Новых внешних вызовов DeepSeek при создании PR нет.

## Состав Git-изменений

Включены код, настройки, formal specs, 1000 synthetic docs /500 вопросов,
135 public docs с лицензиями, mixed1135, отдельные gold/questions, сводные
отчёты, журналы unit-тестов и воспроизводимый 60-document archive.

Не включены около 1 GiB подробных case observations, пересобираемые JSON
индексы и SQLite checkpoints. Они сохранены в исходной локальной рабочей
копии и ранее подготовленном ZIP. Новые прогоны создают их заново; команды
описаны в [README](README.md). Реестры источников и лицензии остаются в Git.

Изменения runtime, конкурсной базы и сабмита в эту ветку не входят.
Корневые README/AGENTS обновлены только для навигации к новой подсистеме.
Для воспроизведения первоначального FINAL_REPORT нужен отдельный checkout
b5ecfdc; для проверки текущего main использовать upstream replay и сохранять
новый source SHA/новые результаты отдельно.
